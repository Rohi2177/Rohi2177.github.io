PROJECT / 01

Implementing a
Password Manager

A vault-broker design for limiting credential exposure after unlock.

THE QUESTION

What happens to stored credentials if an application's interface becomes untrusted after a vault has already been unlocked?

THE APPROACH

The academic project explored separating vault operations from the visible interface and limiting sensitive requests to approved actions.

ONGOING PROJECT

I am continuing to work on my password manager project beyond the dissertation submission.

RECORDED EVALUATION

The submitted dissertation reported 305 passing automated tests and seven skipped. Five security properties were verified in a simplified Tamarin model; these findings do not prove that the whole application is secure.

Read dissertation (PDF) ↗Download project submission (ZIP) ↓View dissertation on GitHub ↗

THE SECURITY DETAILS

01
Separation

A separate broker holds the vault key and handles sensitive operations.

02
Scoped approval

Short-lived, single-use permissions apply to one action on one record.

03
Protection

Argon2id and AES-256-GCM form part of the documented vault protection.

Read the limitations +

This is an academic prototype. Its model has defined boundaries, and a compromised device can still expose information after it is copied or revealed.
